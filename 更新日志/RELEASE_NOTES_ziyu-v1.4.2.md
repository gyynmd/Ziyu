# 字域 v1.4.2 — 正式版更新说明

本次版本以 v1.4.1 为正式基线，按功能移植 LuoShu `main` 中
`cd90150bb6bfa8081c639e684d421c317e5d436a` 的相关改动。

## 新增与修复

- ColorOS 数字族目标策略、专用字库保护、链接候选与缓存身份更新，贯穿物理兼容及 Universal 角色/计划路径；原厂来源和内容校验继续保留。
- 可变轴按字体声明读取与校验，显示自定义轴名并隐藏内部轴，成功元数据按来源版本复用，读取失败和取消不持久缓存。
- 设置中的应用字体诊断：选运行应用检查，或执行一次有界扫描，按目标 PID 的实际映射和命名空间给出来源与处理建议。
- 筛选缓存、前后台查询退避、原有超时预算，以及导入/字体任务前台服务的启动拒绝和系统超时收尾。
- 已保存组合的 TTC/OTC 真正逐面生成：只使用可验证原厂快照，保留字体面顺序、布局、UVS、名称及原厂度量框架，提交前核对来源、逐面契约和输出。专用面、彩色面、未覆盖或共享依赖字形保留原厂；不支持的转换失败时保留原负载。
- 连续两次未完成开机后在下一次挂载前进入保护；OTA 指纹变化后暂缓旧负载，完成原厂重扫并显式重新应用，下一次完整启动实际验证后才解除 OTA 暂缓。新增设置入口及具有所有权校验的恢复、卸载清理。

## 功能边界

- 逐面生成使用已保存组合的静态产物，实际来源 SHA、字重和轴写入证明；历史组合未保存原始选轴参数，因此不声称恢复原始选轴或自动重建每个字重。原厂样式标签保留不代表替换字形具有该样式的独立设计。
- ColorOS 扫描只发现但尚缺可信格式/有效度量的物理槽位仍保留原厂；发现候选不等于已覆盖。FlipFont 只读报告有界且不验证字体内容。
- 应用诊断只能说明可读进程映射及目标命名空间中的来源，无法强制替换应用自带、下载或内存字体；进程退出、复用或负载切换时结果会标为无法确认。
- 开机保护无法替代 Root 管理器或设备恢复工具，跨管理器启动时序、真实 OTA 和卡开机恢复仍需设备验证。

## 验证范围

本次发布工作流负责执行源码回归、Android lint 与单元检查、固定签名、模块打包和哈希核对；各项结果以对应的 GitHub Actions 运行记录为准。设备矩阵当前没有 v1.4.2 实测记录，手机实际显示、三主题交互、不同 Root 管理器的启动时序、真实 OTA 和字体切换耗时仍待设备验证。不从源码变化或自动化构建推断实际提速。
