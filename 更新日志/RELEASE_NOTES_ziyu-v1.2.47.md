# 字域 v1.2.47 Debug

## 原因

旧版手机只读记录显示：当前热切换选择为筑紫400，字体清单中 regular.font
对应新字体，而 .luoshu-payload 仍是上次启动字体；新字体位于本次启动的
不可变 generation 目录和下一启动队列。原升级迁移入口总是选择
.luoshu-payload，导致把旧文件和新清单比较并中止安装。

## 修改

- 使用本次启动有效的 font-live.conf 选择字体负载，同时核对字体选择、请求及目录范围；
  无本次启动热挂载记录时继续使用原私有目录 / 旧公开目录。
- 使用原字体切换身份锁，避免更新与切换同时改写字体状态。当前热字体与待应用选择
  不一致时拒绝混用，要求完成切换后重试更新；不静默改回原厂。
- 先复制到新安装，再按继承的清单校验暂存文件，不再在复制前额外读取全部源文件。
- 校验复用 FontDigestCache，同一文件的多个别名共用一次内容读取；不同实际文件
  仍独立校验，不用永久缓存或文件大小代替内容证明。
- 旧 CRC|size 清单使用 POSIX cksum 校验后转换为 SHA-256；只重写新版暂存清单。
- 保留缺失、损坏、越界链接和过程中变化的文件检查；批量校验明确拒绝后不降级放行。
  Python 未启动时使用原 shell 校验兼容路径。
- 新安装不继承旧启动热挂载指针；从 generation 继承成功后去掉已被继承负载代表的
  下一启动队列记录。原安装的字体树、清单和运行记录保留。
- 新安装 logs/module-update.log 记录迁移来源与 records / uniqueFiles / reusedAliases；
  shell 诊断导出包含此日志。
