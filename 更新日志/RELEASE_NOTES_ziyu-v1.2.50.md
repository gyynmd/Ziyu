# 字域 v1.2.50 Debug

## 已确认的原因

手机 v1.2.49 的只读诊断显示 14 个文件挂载通过，12 个加载路径确认，未挂载 0 个。
原厂 SysFont-Hans/Hant 的第一跳进入 `/data/format_unclear/font/OplusOSUI-*-Regular.ttf`；
该目标又是链接，分别回到 `/system/fonts/SysSans-Hans-Regular.ttf` 和 Hant 对应槽位。
旧代码只查询原厂清单中的第一跳，清单不扫描 /data，所以第二跳遗漏。
证据保存于 `diagnostics/20261010-230951-two-routes-readonly/`。
本次还只读确认三个桥接父目录均为真实目录。

## 修复

加载路径复核在现有可信 stockFontLinks 第一跳基础上，只读指定 ColorOS 桥接目录的
链接元数据。绝对链接在 PID 1 根视图内解释；拒绝父目录符号链接、外部普通文件、越界
目标、循环和过长链。读前读后及接受前核对链接身份，父目录核对设备号、inode 和类型。
不打开外部字体内容，不修改原厂字体度量、不改变 payload 或挂载位置。

只有已通过原有文件内容/权限/挂载校验的原厂链接，完整终点回到已有独立确认的字体
分区槽位且角色相符，才计入已确认加载路径。缺少依据时仍保留待确认提示，并在
unconfirmedDetails 记录具体原因。routeEvidence.stockChain 记录完整链，stockLinkScan
记录读取、复用、快照稳定性及确认数量。原有启动深度复核和成功后状态收敛继续使用。

## 优化

- 链终点和桥接链接缓存只存活于单轮复核，避免重复读取；不同字体切换不共享外部链接缓存。
- 两条路径通过静态链确认后，未确认集合为空，已有流程直接跳过额外进程路径扫描。
- UI 缓存检查逐行读取 /proc/PID/maps，避免整份映射字符串及 splitlines 列表分配；
  按字符串取得映射文件名，保留原有 PID 启动时间、文件对象身份和旧缓存判断。

优化集中在复核与缓存检查，不改字体生成、挂载选择、回滚或用户确认刷新流程。
未测量手机切换耗时，不声称具体加速比例。
