# 字域 v1.2.46 Debug

## 依据

ADB 只读检查的设备仍为 v1.2.44。12:15 的筑紫400任务返回 `liveApplied=true`、
`rebootRequired=false`；本次启动的热挂载记录和请求编号与任务一致。
但任务包装将热挂载写为 `reused=true` 且丢失热挂载 / 重启字段，App 完成处理又自行推断重启需求。
应用确认正文及 MIUIX / COUI 对话框副标题也固定要求或建议完整重启。

## 修改

- 任务记录与状态接口增加独立的 `liveApplied`、`rebootRequired` 字段。
- 热挂载成功与无需生成的重复应用分别记录；未知重启状态返回 JSON null，保留旧接口兼容回退。
- App 优先使用任务的明确重启结果和原完成消息；热挂载成功不进入自动重启倒计时。
- 应用前说明以任务结果确定重启需求，保留临时 Root 的软重启指引。
- 新增只读 SystemUI 字体缓存检测，比较进程映射对象与该进程当前可见字体的设备号、inode 和大小。
- 检测到 SystemUI 旧映射时，任务显示系统界面仍保留旧缓存；App 提供用户确认的 KernelSU 软重启刷新和稍后处理选项。
- 同时记录 Zygote / system_server 的映射证据，但只用 SystemUI 观察结果触发界面缓存提示；权限不足或无可比较映射记为 unknown，不推断已刷新。
- 诊断导出包含 `config/font-ui-cache.json`；不修改进程、不写旧字体文件，也不自动重启。
- 真实需要重启、恢复默认、模块升级和挂载模式切换继续保留其重启流程。
