# ColorOS 字体适配

字域面向 Android 系统字体路由，不通过固定机型文件白名单决定是否安装。应用时扫描当前设备可见的分区、字体配置、XML 引用、字体别名、样式和字重，再准备并验证对应负载。ColorOS 的扩展处理是设备自适应引擎的一部分，不代表每个 ColorOS 版本和分区布局均已完成真机验收。

## ColorOS 扩展

- 扫描 ROM 实际存在的 system、product、system_ext 及 OEM 字体目录与字体 XML。
- 支持根据设备实际配置生成字体槽；针对 ColorOS 的字体族和状态栏/系统 UI 路由有专项处理。
- 按设备目录动态发现 `OSans-*Digits*` TTF/OTF 数字字体并遵守 `osans_digits` 开关；关闭时清理字域先前创建的数字别名。`OSans-RC*` 生僻字与 `OSans-Ext*` 占位回退族保留原厂。
- SysFont 断链或循环链接可以作为扫描候选，但路径链接本身不证明目标字体内容可信或已经加载；只有原厂快照、目标字体身份、路由与运行时证据通过后才确认结果。
- 只读检查 ColorOS FlipFont/桥接目录的有限链接元数据，为主题字体路径提供线索；不改写主题字体设置，也不把该检查当作字体覆盖成功。
- ColorOS 字体度量处理保留原厂度量和字体表，对变更表进行编译，未变化字体表尽量复用源数据。
- 部分槽位无法安全映射时保留原厂目标并报告警告；没有可验证成功的目标或事务不能安全提交时报告失败。

字域不会默认替换不存在的 ROM 目标，不覆盖完整 `fonts.xml`，不打包未经授权的系统字体，也不因某个 ColorOS 型号的诊断结果把其他型号标记为已支持。

## 使用与排查

1. 安装与 App 版本匹配的字域模块，先选择用户需要的挂载方式并按提示重启验证。
2. 导入自有字体、选择中文/英文/数字来源后应用。
3. 在“挂载详情”区分后端、实际实现、字体路由与加载证据；出现部分槽位警告时查看具体路径。
4. 仍有待确认路径时，从“字体刷写 → 日志”导出诊断报告；需要设备分区数据时运行 `common/font_partition_compat_report.sh`，该只读脚本会在其所在目录生成报告。

App 自带字体、网页 WebFont、图片文字和 SystemUI 已经缓存的字体不一定受系统文件挂载影响。热挂载成功只证明 PID 1 的文件与路由验证通过，不等同于所有界面已刷新。

## 真机验收

ColorOS 的当前验证状态以 [`TEST_MATRIX.md`](TEST_MATRIX.md) 为准。v1.4.2 的自动化检查和历史只读 ADB 记录均不替代当前版本的完整安装、路由、字体显示、恢复和卸载真机验收，也不能据一个机型推断其他 ColorOS 构建已通过。
