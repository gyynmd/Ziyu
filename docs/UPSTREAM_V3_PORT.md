来源为 LuoShu 正式标签 `refactor-v3.0.0`，提交 `3e7e19b9f2b0899a326d0ce337602c006b90f233`。本次在字域 v1.3.0 源码基础上按功能适配，版本号和在线更新信息仍指向已发布版本。

## 实现范围

- 两套组合生成器共用新的平顶字形探针、中文比例和基线校正；同一个英数字体使用同一套变换。英数变换都在原始中文基底上计算，避免先替换英文影响后续数字对齐。
- 组合页面新增英数大小（±15%）、上下位置（±10%）和恢复默认。Material、MIUIx、COUI 页面共用控件；App 保存选择，组合方案 JSON 与完整备份包含微调参数。旧方案缺少参数时按零处理。
- 微调参数贯通 Root bridge、生成暂存记录、后台任务、生成清单和 Python 引擎；整数范围在 App、Shell 和 Python 中分别限制。只有配套模块明确报告支持时才能使用非零微调，避免旧模块忽略参数。
- 组合缓存身份包含引擎内容和微调值；校验缓存输出摘要、字体格式以及处理前后源文件和引擎身份。非零微调不能走同源字体直接复制路径；TTC 仍由生成器选择字体面。
- 沿用字域已有实例缓存、并行字体准备和兼容告警。英文与数字保留同一小范围字形集；缓存按实际选中的 TTC 面、字重和轴值区分。同字体、同轴的英数请求顺序复用实例，中文仍可并行准备。缓存命中后继续做各槽位的必要字形检查。
- HyperOS 诊断优先采样设备真实存在的西文路由，记录采集进程内符号链接的目标。导出只包含允许的系统字体路径，其他目标显示为 `other`；该观察不替代 PID 1 挂载或应用缓存验证。

上游日志误报修复已有字域对应实现。任务监督、挂载选择、热切换、失败回滚和字体负载提交继续使用字域现有流程。
