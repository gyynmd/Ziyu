## 复查中新合入的 ColorOS 英文/数字覆盖修复

`cd90150b` 合并 PR #294，新增 `coloros_latin_policy.py`、`coloros_flipfont.sh`，调整 ColorOS 15/16 映射与目标缓存身份。值得借鉴的具体行为：

- 把 `OSans-*Digits*` 数字字体族纳入可控覆盖，同时保护 `OSans-RC*` 生僻字与 `OSans-Ext*` 占位回退字库。
- 原厂 `SysFont-*` 符号链接即使悬空或成环，也按实际存在的链接槽位识别；不能只用 `-e` 或 `-f` 判定。
- 将覆盖策略修订和分组状态纳入目标缓存键，防止更新模块后继续命中旧目标名单。
- 只读检查 OPlus flip 字体的二次链接，区分 `/system/fonts` 路由和主题重定向到 `/data` 的路线；诊断不会改写主题字体或替代覆盖修复。

字域 `coloros_global.sh` 已包含固定的 `OSans-Solid-Digits-VF.ttf`，但尚无上游这一完整分组策略；兼容安全切换的旧映射器也未包含 OSans 数字族。字域当前 `-e`/`-f` 检查仍会跳过悬空/成环的 SysFont 链接。这一差异确实值得独立适配，但必须保留字域原厂快照可信来源、PID 1 命名空间验证、回滚及其他 ROM 边界，不能把有链接当作已验证的原厂字体内容。本次先完成代码判断，没有在正在构建的 1.4 中修改这部分接管范围。

本次没有接入上游启动页资源、整套挂载核心、完整 HyperOS 接管或 RootSession。已接入的模板读取优化由字域现有正式发布工作流中的模板回归及其他源码检查核验；自动化检查与手机验收分别报告。
