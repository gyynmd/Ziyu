# 洛书最新代码对比与移植判断（2026-10-13）

实时读取 GitHub Releases 和远端 refs：最新正式版为 `refactor-v3.0.0`，提交 `3e7e19b9f2b0899a326d0ce337602c006b90f233`；最新 main 为 `55238353bbe199aa34e621a7661dfe2e1c9a9989`（10 月 13 日）。上游 `CHANGELOG.md` 明确把 3.0 之后的内容列为未发布，下一正式版计划 3.3.3。

字域已有 3.0 的组合英数对齐、大小/基线微调、实例缓存与日志过滤适配，详见 `UPSTREAM_V3_PORT.md`。本次审阅的是其后的代码，未把未发布 main 当作正式版验收。

| 新增方向 | 代码与实际作用 | 字域现状和判断 |
| --- | --- | --- |
| 字体能力统一识别 | `font_capability.py` 统一真实字重、可变轴、TTC/OTC 字体面及样式/字库保护 | 字域已有字重、角色和轴处理；可借鉴其统一判定，但要合并现有编译与缓存契约，避免重复引擎。 |
| 集合目标生成 | `composite_collection_build.py`、`composite_collection_contract.py` 为系统集合逐面生成并核对字体面与生成证明，含可变 CFF2 | 字域支持集合来源及原厂集合壳，但兼容组合路径不等价于这套完整逐面生成。值得独立适配，须检查 face 索引、保留字库、度量、缓存和回滚。 |
| 模板按需采集 | `device_font_template_base.py` 延后内部名称索引、懒加载所需字体表 | 已选入 1.4 优化：移植 `852297117606ca37436b999b6307fd598742bca7` 的单点读取优化，保留原解析、哈希与验证。没有真机提速比例。 |
| App 性能 | `RootSession.kt` 复用有空闲关闭、取消/超时清理的一条 Root 会话；轮询退避、字体筛选结果缓存和前台服务超时处理 | 字域当前采用单次 Root 请求。筛选/可见性轮询/超时处理适合分项接入；共享 Root 会话需要先适配请求所有权、并发、临时 Root 和清理语义。 |
| HyperOS 覆盖 | 新增分类覆盖设置、XML/主题字体和 WebView 路由处理、时钟字符保护 | 会影响字体接管范围和系统主题路径，需按字域挂载策略独立适配；不应直接用于 vivo/ColorOS。 |
| 未覆盖应用定位 | `font_coverage_locator.py`、`device_font_process_audit.py` 按应用进程命名空间检查字体来源，并提供应用选择与扫描 | 可改进“部分界面生效”的诊断。只读核查本身不会让 App 内置字体自动替换，接入时需控制扫描范围和开销。 |
| 启动/卸载/OTA 稳定性 | `boot_loop_guard.sh`、`system_ota_guard.sh` 等处理连续未完成启动、安全模式、OTA 首次启动与卸载清理 | 字域已有启动验证、恢复和临时 Root 流程。原则值得借鉴，实现须统一计数与事务，防止软重启或服务未完成被误算失败。 |

建议后续顺序：先做筛选缓存、可见性轮询及前台服务超时，再适配真实轴/字体能力和集合生成，其后接入只读未覆盖定位。HyperOS 接管和共享 Root 会话单独验证。

本次没有接入上游启动页资源、整套挂载核心、完整 HyperOS 接管或 RootSession。已接入的模板读取优化由字域现有正式发布工作流中的模板回归及其他源码检查核验；自动化检查与手机验收分别报告。
